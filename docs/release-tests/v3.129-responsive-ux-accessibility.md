# v3.129 Responsive UX & Accessibility Manual Checklist

Live Hermes window checks.

## Dashboard across real sizes
- [ ] 3440x1440: panels comfortable; no horizontal squeeze; shelves legible.
- [ ] 2560x1440 and 1920x1080: metadata, duration badges, long titles/channels/descriptions legible.
- [ ] Narrow laptop-sized Hermes window (and 100%/125%/150% Windows scaling): media panel stacks over
      the stats/description (no horizontal overflow), long titles clamp, missing thumbnails show the
      URL fallback, empty shelves show their placeholder, very large playlists scroll.
- [ ] Shelf labels and Now Playing hierarchy remain readable at every size.

## Floating player
- [ ] Minimum supported width/height (Mini): play/pause, seek, next/prev stay reachable and usable.
- [ ] No control collisions or text clipping when resized to the smallest Size.
- [ ] Geometry restoration after float -> dock -> float.

## Accessibility
- [ ] Tab order: transport controls, then timeline, then selects, then search (logical).
- [ ] Enter activates focused buttons; Space toggles play/pause; Escape exits fullscreen.
- [ ] Visible focus ring on every interactive control via keyboard.
- [ ] Tooltips (title) present on icon-only transport controls.
- [ ] Play/Pause and status are conveyed by text, not colour alone (no colour-only state).
- [ ] Disabled controls are clearly dimmed and not activatable.
- [ ] Typing in Hermes chat is never stolen by the plugin (Escape only exits fullscreen).
